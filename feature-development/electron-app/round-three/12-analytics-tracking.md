# TODO

We need a way to be able to track user activity within the application without disclosing information about their source code. One of the hallmark benefits of using this application is we don't store source code that is analyzed in any way. It is imperative for us to understand where users are running into problems when the application is creating errors or other issues, for debugging, RUM tracking, performance tracking, and other tracking metrics that may be helpful in identifying issues early on, remediating problems, making improvements to the code base, and also specifically and very importantly, calibrating the algorithms of the application over time through identification of spurious issues in analyses and in user feedback.

The goal here is to identify a modern optimal tracking solution. We want to be able to consider the possibility that users may be offline for an extended period of time and that tracking information that takes place with the user's experience may need to be queued up and sent to our servers when they come back online. This tracking experience should be transparent to the user. They should know that it's happening, although they should be provided with settings in the settings.tsx view to enable or disable specific tracking. We should provide them with several examples, not just one example of turning it on or not, but providing the different types of tracking, such as:

- tracking to help improve performance of the application
- tracking to help identify spurious issues and improve our algorithms
- tracking to identify errors or bugs that users may be running into Of course, if there are other things that we should include in that pane, I leave it up to you. I also leave it up to you to provide a proper disclosure to users so they know transparently what it is that we track and do not track.

I don't intend to use a paid platform for tracking. If possible, I would like to try and manage this with as low of a cost as possible. I encourage you to figure out what may be an appropriate long-term solution for tracking these various requirements. If there are open source libraries that are available for this that I can then send to a postgres database, or some other low-cost solution that I can easily set up with open source UI or other reporting tools, that would be ideal. Part of this document is exploration, as much as it is implementation.
